# Baseline optimization and evaluation

The README §§5.4/6 specifies qualitative hierarchy and customer-dependent weighting without equations. The implementation chooses an open-source SciPy/HiGHS MILP and documents the defaults here. It replans a rolling horizon (12 five-minute steps by default), applies its first action through the independent shield, and replans from feedback next interval. Planning and dispatch cadence are currently identical; no unvalidated cached plan is reused.

Per interval the MILP chooses compute/cooling, charge/discharge, grid import, generator output, stored battery energy, generator commitment/startup, exclusive battery direction, missed units, temperature, served work and compute commitment. The objective is grid cost + fuel/variable/startup/shutdown costs + cell-throughput degradation + configured missed-work penalty (default 100 USD/abstract unit). Useful compute per energy and cost per useful unit are reported metrics. This weighted linear objective avoids an unstable ratio at zero output while encoding README reliability/throughput/cost priorities. No emissions price is enabled by default.

Constraints match the discrete physics: electrical balance including auxiliary demand, compute capacity/idle commitment, work arrival and cumulative EDF deadline balances, battery efficiency/SOC/ramp and exclusive flow, generator min/max/commitment/startup/ramp/up/down history, cooling COP/ramp/response lag, and thermal bounds. Terminal battery energy cannot be lower than the configured episode-initial energy; this prevents free terminal depletion without ratcheting the reserve upward after each charging interval. Explicit deferrable arrival fractions and queued deadlines allow shifting. Omitted workload metadata is conservatively treated as due now. Future active capacity is respected; future generator availability is held at current telemetry because it is not yet a forecast signal.

When prediction intervals are present, the default planner selects upper demand/price/ambient and lower grid/active-capacity bounds. Set `use_prediction_intervals=False` for nominal-point comparison. This is conservative point selection, not a probabilistic/chance-constrained guarantee: correlated extremes, cold-side thermal risk and calibration error require the ML/safety workstreams. Distributional optimization remains an extension. Import/export arbitrage, renewables, calibrated SLA revenue and emissions caps are not modeled by this baseline. Horizons are limited to 288 intervals to bound dense model construction memory. End-of-horizon generator commitments are carried by state on replanning, with constraints enforced over the available horizon.

Only solver status `optimal` produces an action. `timeout`, `infeasible`, `unbounded`, `invalid_forecast`, `invalid_state`, `solver_error`, and `invalid_solution` remain explicit. Timeout incumbents are conservatively discarded. Solver bounds, rows, integrality and finite values are independently checked. A failed plan raises `PlanningFailure` at the policy boundary; the dispatcher marks a rule fallback and still asks the shield. Shield rejection or communication/audit error stops before simulator stepping. Physical feasibility of a fallback is not guaranteed under a compound outage; the simulator exposes unmet load/deadlines and the real safety/controller owns enforcement.

Evaluation runs fresh policy/simulator instances on identical synthetic scenarios, initial conditions and seeds. Four CLI comparisons are rule, fixed schedule, persistence-forecast MILP, and explicitly offline hindsight MILP. Hindsight uses only a rolling 12-step oracle of demand, weather, price and grid restrictions, not a globally optimal full-episode solution. It is rejected by normal planners. External learned policies use `CallablePolicyAdapter`, or implement `PolicyProtocol`; RL uses the Gym wrapper.

Metrics distinguish operating cost from penalized objective, useful throughput, completion/misses/pending work, imported energy and peak power, cooling, battery throughput/wear/cycles/terminal SOC, generator use, unserved energy, physical constraint events, actuator adjustments, shield intervention/rejection, fallback use, policy/optimization runtime and simulator failures. Failures remain flagged; they are never ranked as successful zero-cost runs. Terminal temperature and battery energy are included because policies can consume different stored energy/thermal headroom. Finite-horizon raw costs are not a general savings claim; assess service and terminal states as well.
